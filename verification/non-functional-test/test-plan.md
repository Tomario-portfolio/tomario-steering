# 非機能試験計画書

## ステータス
確定（2026-07 に初版を定義。2026-09 に手順書整備に合わせて確認項目を拡充）

## 1. 目的・方針

「Auto Scaling を設定した」「バックアップを取得している」ことと、「実際に閾値どおりスケールする」
「実際にリストアできる」ことは別問題である。prod 同等構成の staging 環境で、以下の観点が
設計どおりに機能することを**実測で**確認し、検証済みの構成を production へ引き継ぐ。

- 性能：水平スケーリングが設計値どおり動作するか、目標スループットを捌けるか
- 可用性・信頼性：障害発生時／正常デプロイ時に自動復旧・無停止性が保たれるか、データ不整合が生じないか
- 復旧：バックアップから実際に復旧でき、RTO / RPO が許容範囲か
- 運用：監視・アラートが実際に発報するか、ロールバック・インフラ再構築ができるか
- セキュリティ：既知の脆弱性が残っていないか、境界防御・証跡が有効に機能しているか

**production 固有の追加検証**：production では staging に無い WAF・Security Hub・AWS Config を導入する（`security-environment-design.md`、面接期間のみ有効化。WAF は cost-stop/start に組み込む）。これらの有効性・誤検知・レイテンシ影響・ログ／アラート・緊急デタッチ手順を production（未公開期間）で追加検証する。項番は P-09 / M-07・M-08 / O-05 / S-07〜S-10。

> WAF Web ACL の cost-stop/start 組み込み自体（作成／関連付け／削除が壊れず回ること）は、cost-stop/start を日常運用として繰り返す中で自然に確認できるため、独立した試験項目（旧 O-04）としては置かず、`verification/env/production-only-test-items.md` の運用メモ側で扱う（2026-09-14）。

## 3. 試験範囲（実施する／しない）

| 試験種別 | 実施 | 理由 |
|---|---|---|
| 性能試験（負荷試験・Auto Scaling） | ○ | 水平スケーリングの実挙動を確認する |
| 目標スループット試験 | ○（目標値 TBD） | 非機能要件に目標 rps を追記してから判定基準を確定する |
| 限界性能試験（頭打ち点・ボトルネック特定） | × | 負荷を継続的にかけるコストに見合わないと判断。ポートフォリオ範囲外 |
| 耐久試験（ロングラン） | × | 非商用のため。数日分の課金に見合わない |
| 信頼性試験（障害試験） | ○ | サーキットブレーカー・タスク自動復旧の実挙動を確認する |
| 無停止デプロイ試験 | ○ | 異常系だけでなく、正常デプロイ時のリクエスト継続性も確認する |
| AZ 障害・RDS フェイルオーバー試験 | × | Multi-AZ 無効構成のため実施不可。将来 Multi-AZ 化する場合は prod 未公開期間に実施する |
| 復旧試験（DR 訓練・PITR） | ○ | 本番で初めてリストアを試すリスクを回避する |
| リージョン障害試験 | × | シングルリージョン構成のため対象外 |
| 運用試験（監視・アラート発報） | ○ | 監視が実際に機能することを確認する |
| 運用試験（デプロイロールバック） | ○ | promote フローの切り戻し手順を実演して検証する |
| 運用試験（インフラ再構築 / cost-stop・start） | ○ | Terraform からのインフラ復旧を確認する（日常運用で実施済み） |
| セキュリティ試験（脆弱性診断・境界防御・証跡） | ○ | 依存関係・イメージ・TLS・ネットワーク境界・GuardDuty / CloudTrail |
| WAF 試験（ルール有効性・誤検知・レイテンシ・ログ・アラート） | ○（production のみ） | production に導入する WAF が意図どおり防御し、正常業務を誤検知せず、性能・運用に問題が出ないことを確認する |
| Security Hub / AWS Config 検出結果レビュー | ○（production のみ） | 有効化後の Critical / High findings・NON_COMPLIANT リソースをレビューし、対応方針を記録する |
| WAF の cost-stop/start 組み込み・緊急デタッチ | ○（production のみ） | Web ACL の作成／association／削除が回ること、誤検知時に緊急デタッチできることを確認する |
| 移行試験 | × | 新規構築のため対象外（既存システムからの移行なし） |

## 4. 確認項目一覧

準備・後始末・任意ステップ（P-01/P-06/P-07、A-05、B-02/B-04/B-05/B-06、S-06 等）は手順書側に記載する。

## 5. 実施順序

```
【staging】
テストデータ投入
  → P-00（ベースライン） → P-01..P-08（負荷試験・Auto Scaling・目標スループット）
  → A-01..A-04（障害試験・無停止デプロイ）
  → B-01..B-03（DR 訓練・PITR）
  → M-01..M-06（監視・アラート発報・ログ追跡）
  → O-01..O-02（ロールバック・インフラ再構築）
  → S-01..S-05（脆弱性診断・境界防御・証跡）

【production（未公開期間、WAF・Security Hub・AWS Config 有効化後）】
  WAF を COUNT モードで作成
  → S-08（誤検知確認：一定期間ログを見て除外設定）→ BLOCK へ切替
  → S-07（マネージドルールの有効性：攻撃ペイロードのブロック確認）
  → M-07（WAF ログ配信確認）→ M-08（BlockedRequests アラート発報）
  → P-09（WAF 有効／無効のレイテンシ差分）
  → O-05（緊急デタッチ手順）
  → S-09（Security Hub findings レビュー）→ S-10（AWS Config コンプライアンス評価）
```

## 6. 合否判定・課題管理

- 各項番の判定基準をすべて満たした場合に「合格」とする
- 満たさない項目は課題として起票し、修正後に該当項番を再試験する
- 参考項目（P-05 の p95、B-03a）は合否判定の対象外。実測値の記録のみ行い、目標値は非機能要件定義書へのフィードバックとする
- P-08 の目標値（目標 rps）は非機能要件定義書への追記後に確定し、本計画書を更新する
